## Purpose of this record

The operational FAWLTY learning primitive is already represented in GitHub by `src/basil/fawlty.py`: evidence-referenced learning records, optional expected-versus-actual calibration and an explicit approval gate for material or cross-component change.

A separate Drive-based archive-learning pilot began on 28 August 2026. This file preserves the public-safe provenance and status of that pilot without copying the private/historical corpus into the public repository and without treating its discoveries as current authority.

## Governing pilot correction

FAWLTY Archive Learning Pilot v0.2 corrected an earlier tendency to extract lessons too quickly from a bounded recent archive. Its governing rule is **discovery before learning**.

The pilot therefore requires this sequence:

1. broad archaeology
2. lineage mapping
3. evidence triage
4. learning extraction
5. cross-era comparison
6. current-relevance assessment
7. permission-gated intervention
8. closed-loop validation after an approved intervention

Historical usefulness does not equal current authority. Duplicates are not independent corroboration. Migrated file dates are not unquestionable chronology. Retrospective summaries are source maps, not substitutes for primary evidence.

## Discovery and learning remain separate

The pilot distinguishes two stores:

- **Discovery Register:** possible source material captured before judgement
- **Learning Register:** lessons admitted only after lineage and evidence review

This separation is material. A search result, archive memo, historical task row or abandoned build does not become a FAWLTY lesson merely because it was found.

## Public/private boundary

The full archaeology corpus remains in Drive because it includes historical operational material, possible personal/contextual content, sensitive candidates and primary evidence that is inappropriate for a public source repository. One inspected 2024 candidate contained credentials; the pilot explicitly excludes those secrets from propagation.

GitHub should therefore preserve method, provenance, maturity and evidence boundaries rather than mirror the private corpus.
